Contrast rule that keeps the measured colour untouched. The name sits on a solid strip of the winner band. Text is paper when that band's relative luminance is under 0.45, ink above it. The strip #C2854A measures 0.29, so it carries paper — the hue itself is never lightened, darkened or saturated to make the type readable.

Shape lock. Actions are pills, cards 20, chips 12, and the colour field is 0 — full bleed, because rounding a measured band would crop data. Spacing on a 4 grid, 20 gutter, 16 between stack cards.

Motion — the one delight, frame by frame

Shutter to card. Everything else in the app is under 150 ms or is the platform default. The bands are revealed by clipping, never by animating height, so nothing reflows and the type never jumps.

Curves. Reveal is spring(stiffness 220, damping 1) on the clip, never a bezier with an ease-in on the entrance. Name fade is 120 ms linear, starting at 330 ms so it arrives into a surface that has already stopped moving. Card entry from scale(.96) + opacity 0, never from scale 0.

Haptics, one per action, on the same frame as the visual. Light tick on shutter press-in. Success tick when the card files. Nothing on scroll, nothing in a loop, nothing while the model writes — a 1.2 s wait is not an event.

The stack is the second motion surface, and it is scroll-linked, not decorative. Cards scale .97 → 1 and straighten from 1.2° to 0° as they reach centre, so the evening you are looking at is the only one square. Driven from the scroll offset on the render thread; zero lines of animation code if the frame budget can't hold 60 fps on the target device, in which case the rotation is cut first.

Reduce Motion collapses all of it to a 120 ms cross-fade from preview to finished card. The card still appears, the name still appears, nothing slides.

What is deliberately not animated: the wording line. Gemma takes ~1.2 s and the card is already finished when it arrives, so the line fades in once at 120 ms. No shimmer, no skeleton, no "thinking" indicator — a spinner would advertise a delay nobody needs to feel.

Responsive — three width classes, one card

The card is an object with a fixed aspect, so it never stretches. What changes is how many you can see and where the detail lives.

Compact  ·  < 600 dp phone portrait — the four screens above

Stack 1-up. Gutter 20. Preview card 186 dp, rotated 1.2°.

Medium  ·  600–840 dp foldable open, large phone landscape, tablet portrait

Stack 2-up, 16 gap. Card caps at 340 dp wide and centres — it does not widen. Tonight keeps one column with the preview card at 240 dp.

Expanded  ·  ≥ 840 dp tablet landscape, foldable at full width

Two panes: stack left at 38%, card detail right, card max 420 dp with a 68% field. No bottom nav appears at any width — the app has four destinations and a back gesture.

Font scale is the harder responsive case, not width. Up to 1.15× nothing changes. Past that the display ramp stops scaling proportionally (44 → capped 34) so "in 14 min" never pushes the preview card off screen, and the 1.2° rotation is dropped because rotated text at large scale reads badly. Every tap target stays ≥ 48 dp, including the two text actions on the card screen, which get invisible padding rather than a bigger label.

Corners. Compose RoundedCornerShape is circular, not continuous. The 20 dp card radius is drawn as a squircle path, because the difference is exactly the thing that reads as "native iOS app" versus "web page in a wrapper" — and it costs one GenericShape, not a library.

Landscape on a phone is not supported in v1. Stated so it is a decision rather than an oversight: the capture screen is portrait by nature, and a second layout for a state nobody shoots in is scope we do not have before 11 Oct.
